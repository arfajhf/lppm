# Daftar dokumen dan langkah SOP hibah

Diperbarui 20 November 2026. Lampiran [panduan pengguna](panduan_pengguna_hibah.md). Daftar berikut dicocokkan dengan **52 definisi** pada `config/grant_sop.php` dan pengendalian tambahan service/controller. Ini daftar unggahan per langkah, bukan pernyataan bahwa seluruh proses institusi telah selesai.

Gunakan PDF untuk paket QA. Batas unggahan 10 MB per berkas. PDF diwajibkan khusus portofolio reviewer, borang penilaian dan scan arsip; unggahan umum mengikuti jenis yang diizinkan form. File yang sesuai dapat dipakai ulang melalui pilihan dokumen existing. Baris tanpa file tetap meminta data dan/atau checklist pada form.

Tandai dokumen simulasi sebagai DOKUMEN UJI QA LOKAL. Dokumen uji bukan tanda tangan, transfer atau pengiriman surat institusi yang sebenarnya.

## 4. Bukti di luar satu formulir SOP

| Kegiatan | Pelaksana | Isi/bukti yang dibutuhkan |
|---|---|---|
| Pendaftaran calon reviewer (35.2) | Kandidat atau Admin | Periode reviewer terbuka, asal, keahlian, instansi, portofolio **PDF**. |
| Penugasan proposal/monev/seminar | Admin | Akun reviewer aktif, jenis tugas sesuai tahap, jadwal dan catatan surat tugas/lokasi/kriteria. Ketua/anggota tim tidak boleh menilai sendiri. |
| Penilaian proposal, monev (11.3), seminar (9.3) | Reviewer ditugaskan | Skor, hasil, referensi kriteria, kekuatan/capaian, perbaikan, rekomendasi dan borang **PDF**. Seminar juga memerlukan konfirmasi pemaparan. |
| Logbook (10.1/18.4) | Pengusul | Tanggal kegiatan tidak melewati hari ini dan catatan hasil/kendala pada tahap pelaksanaan. |
| Unggahan laporan (10.2/39.1) | Pengusul | Dokumen kemajuan/akhir/keuangan/luaran; versi, aktor dan waktu tercatat. Form SOP terkait membuat laporan terstruktur. |
| Rekap usulan/kontrak (38.2/38.4) | Role yang berwenang | Ekspor CSV periode sesuai lingkup, bukan unggahan baru setiap proposal. |

## 5. Catatan urutan

- **35.5** tidak memindahkan status reviewer, tetapi kelengkapannya wajib sebelum penugasan reviewer internal.
- **5.3** memakai pengesahan 5.2. Gunakan tahap/putaran aktif setelah revisi, bukan sekadar label file lama.
- Monev: jadwal 11.1 -> penugasan -> surat tugas 11.2 -> penilaian -> hasil 11.4 -> tindak lanjut 11.5 -> Admin lanjut.
- Seminar: jadwal 9.1 -> penugasan -> pemaparan 9.2 -> penilaian -> Admin lanjut -> perbaikan 9.4.
- **18.1** diikuti penetapan nilai hibah pada form keputusan. **18.3/18.7** memeriksa nominal 70/30.
- **40.3** wajib PDF termasuk saat memakai dokumen lama.
- **40.6** merupakan tindak lanjut berkala sesudah selesai, tanpa menghapus arsip elektronik.
- Langkah tahunan tidak menghambat penutupan proposal individual; bukti sinkronisasi dicatat manual, bukan konektor API otomatis.

Untuk perpindahan role/tahap, gunakan [panduan utama](panduan_pengguna_hibah.md). Untuk hasil pemeriksaan, gunakan [checklist QA](checklist_qa_hibah.md).
